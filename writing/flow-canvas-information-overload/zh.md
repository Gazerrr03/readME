# 当信息开始替我思考

Published: 2026-08-09
Last edited: 2026-08-13
Tag: 设计

## 前言

没记错的话是在去年的八月，或许至今我都不会忘记那时每天依赖着 ChatGPT 学习的经历，因为那让我构思起了一件事：一个画布上的多分支对话，也许可以取代传统 LUI 的线性对话。

所以我开始做一个 Flow canvas 产品。

在这个过程中，我见证了 AI workflow 的兴起和淡出，见证了 Skill 的出现，也看着 multi-agent 慢慢成为行业里的一种技术正确。新东西一个接一个地冒出来，迭代快得让人发慌——回头看我们那个只是纯 LLM API calling 的东西，越来越觉得它不够吸引人，也不够酷了。

渐渐地，Flow canvas 在我们的眼里没那么酷了，但不得不承认，我心中仍然对这个不成熟的点子抱有感情。

为此我纠结了很久，那是一种说不出的痛苦——尽管在生理和心理上，它都没有给我带来实质的痛感。

我积极去投递大厂简历，却三顾腾讯而不入，最后又亲手放弃了自己的机会，颇有左右脑互搏的意味。

我全盘否定过去本科三年的努力，理想主义地认为只要还抱有创意的激情，纵使辍学都无所谓。为此，我甚至给自己找了说服自己放弃推免的借口，并称之为"挑食"。

我反复在相信自己和质疑自己之间辗转。

直到参加 AdventureX hackathon，我才发现了第一层的"信息过载"。Coding Agent 给了每个即便不懂 coding 的人实现想法的机会，大家都在说要做酷的事情。那么酷的定位到底是什么呢？我想我一直以"二极管"式的思维去理解它。

但 AdventureX 给我的并不是焦虑，恰恰相反，它让我重新被激励了。

在此之前，我太想做出酷的东西了，却又不理解真正的酷，一直把"看起来高大上"当作标尺，反复纠结，还不断给自己的行为找一些听起来很酷的理由。

来了 hackathon 之后我才发现，做酷的事情本身也可以很摇滚——它不需要先被包装成某种宏大的东西。

我和很多年轻的参与者交流，有的人正在积极地用 AI 去做 OPC，把一个人的能力边界往外推；也有的人没有把 AI 当成展示技术的东西，而是真的在用它解决自己的生活问题。那些问题可能很小，甚至不值得被包装成一个宏大的产品故事，但它们确实让某个人的生活变得更顺手了一点。

这让我重新意识到，所谓"酷"不一定是把更多新名词、新模型和新架构堆在一起。

我心目中的极客，是那些愿意为这个世界贡献酷的东西的人：他重新思考一个大家已经习以为常的事物，觉得它也许可以有另一种形态，于是愿意亲手把这个答案做出来，并且把它交给别人使用。酷不只是一个人的自我表达，也是一种愿意把想法贡献出去的行动。

Flow canvas 正是这样一次尝试：它既是对思维画布形态的一次重新思考，也是对我们已经习惯的 LUI（Linear User Interface）的一次重新审视。它不急着把自己归类成某一种工具，而是先提出一种交互形态，再看人们究竟想用它来做什么。

当然，这个问题或许没有标准答案。至少如果现在问我，我会说：让每个人，无论知识水平高低，都能有一个舒适交互的产品，允许所有人平等地使用，让各自的生活更便捷。那我会认为，这种东西是符合我对酷的直观印象的。

## 从垃圾桶里翻出过去丢弃的纸团

于是，我捡回了 Flow canvas——或者说，真正意义上开始全心投入去打造它。

正是在重新拾起这个被搁置许久的点子时，我意识到自己正被信息过载所困。

我很兴奋，能以时隔一年后的自己重新做这张答卷，我们团队笑称这是一次"文艺复兴"。

而作为考生，我当然很认真。那段时间，我频繁地浏览了很多 Product Hunt 上被大家称赞的产品，也看了很多画布、笔记、AI 工作区和设计工具。每个产品都有一些值得借鉴的地方：这个产品的导航很舒服，那个产品的卡片很漂亮，另一个产品的布局看起来很适合工作。我把它们一个个记下来，再带回 Flow canvas，尝试放进自己的产品里。

## 垃圾未必待在垃圾桶里，垃圾桶里未必是垃圾

在新原型构思阶段的那几天，Flow canvas 确实看起来越来越完整了。它多了很多看起来合理的 UI，也添了不少似乎能提升体验的 layout。

但我很快发现，它正在变得像一个非常常见的画布产品，而不是我原本想做的那个东西——就像一只羽毛未丰的幼雏，用拿来主义的思维，把林子里其它漂亮鸟儿的羽毛粘贴在自己身上。

我原本希望用户看到 Flow canvas 时，不会立刻把它归类成某一种产品：它不是只能画思维导图，也不是只能零散地排布图片。它只定义一种交互形态：用户可以连接和创造卡片。用它规划一次旅行可以，推敲一套复杂的架构可以，甚至和朋友在上面开始一场跑团游戏也可以。

可是当我把越来越多的案例搬进来时，我反而替它决定了它应该长什么样。这和我早期的想法相悖——那时我就想过，能不能引入 GenUI，让每个用户根据自己的工作环境，自适应地生长出最适合自己的界面模式。每一张画布里的卡片就好比一辆车，我们允许用户根据不同的路况随意改装它。

我以为自己是在寻找更好的答案，后来才发现，我只是在寻找别人已经给出的答案。

## 当"盗作者"大言不惭地将自己的盗作定义为创作

这不是我第一次遇到类似的问题。

我记得第一次拿到高分的大学课程设计，恰恰是在我还不懂得去找案例的时候。那时候我没有整理一套完整的前期调研，也没有认真研究任何设计大师，只停留在记住和模仿他们符号的层面。那时我也只是沉下心来，从一个模糊的问题开始，在 Rhino 里建了很多 box，然后不断推、拉、移动它们——实际上，我把创作的很多责任外包给了工具。

好在我运气不错（我会把毫无逻辑却能做出漂亮垃圾的事情定义为运气，因为现在的 Agent，即便你给它烂到爆的提示词，它也有概率抽出一张漂亮的牌），方案的生成过程很顺利，细节也一直在往前走。

老师给了我很高的分数，我也因此以为自己拥有某种设计天赋。

现在回头看，那次设计当然不值得被浪漫化：它闭门造车，也没有真正落实我后来才意识到的那些设计原则。它更像是一次运气很好、生成过程很流畅的练习。但我往后再也没有做过那么顺畅的设计，这件事一直留在我的记忆里。

因为后来我开始学会调研了。

在我的观察里，设计教育经常把调研放在一个非常崇高的位置：一个学生甚至还没有对问题完成基本的定性，就会被要求先去搜集案例、整理资料、分析条件。积极调研当然是好事，但它应该建立在从原点思考一个问题的基础上。否则，调研就很容易变成一种形式主义——我们并不是为了验证自己的判断去看资料，而是把资料当成判断本身。

而落到行为上，学生因为老师的要求去调研，产出的却是连自己也不确定有何意义的资料，随后便觉得已经一劳永逸，一头扎进了设计里。

这同样发生在我身上。

当我自以为掌握了更多设计理论、更多案例，也拥有了更广泛的搜索能力之后，设计反而开始变得痛苦。因为我知道了太多"可能的方向"，所以每一个方向都显得不够好。我会在前期不断做方案，不断比较，不断否定。

等周围的人都动手做得差不多了，我才在深夜里逼迫自己，靠敲诈疲惫的身体换来一点零星的、甚至依旧平庸的创意——这种行为本质上与妓女无异。

我不是没有想法，而是让太多别人的想法，在我自己的想法形成之前就进入了房间。

并且我一直没有真正学会怎么表达：我的思维发散而跳跃，可以很电波系地蹦出很多抽象的念头，却无法把它们描述出来。这体现在我的工作中——我曾相当依赖 plan mode，但多数时候，它只是对我想法的部分提炼。我自认为在和 AI 结对工作时，AI 只拿走了它最需要的那部分上下文，可实际干下来，过程对我来说却常常是个黑盒：我不清楚它是否真的 get 到了我所有的想法。

## 在那满溢而出的上下文口袋里，究竟要装下什么

信息过载不只是信息太多。

> 更准确地说，它夺走的是一个人决定信息何时进入、以什么关系进入当前思考的权力。

最近一位朋友把他写的《Why Obelisk》这篇 blog 分享给我，读完后里面很多话都让我感同身受，尤其是检索那一段：检索本身就是一次关于时机、范围和权威性的判断；一条略有偏差、或者只是属于另一个时刻的记忆，不会中性进入上下文，它会跟当前证据竞争，抢走你的注意力，把一个旧结论悄悄变成当下的约束。

在一个产品团队里，解决信息过载有时并不意味着建立更完整的资料库，也不意味着每个人都要参与每一个判断。

一个有 taste 的人，如果对某件事情形成了足够明确的判断，并且愿意交付一个有把握的结果，那么其他人就不必再为这件事消耗信息带宽。这在国内一些大厂的环境里也能看到——未来的互联网行业，或许主要会收敛成两类人：价值工程师和优化工程师。

这不仅是减少信息传递过程的熵增，其实也是在交付信任。

《纳瓦尔宝典》里也提到过，勇于承担风险、敢于以个人名义揽下成败，是获取巨大回报和自主权的必经之路。

"我已经看过了，这个结果可以继续往下做。"这句话的价值，不是它包含了多少信息，而是它替别人承担了一部分判断。没有这种信任，团队就会不断重复调研、重复解释、重复讨论，最后把本来可以向前移动的事情困在信息里。

所以真正重要的不是让所有人都知道更多，而是让每个人都知道：什么事情已经足够确定，什么事情仍然值得继续怀疑。

## 推理分析、抽象提炼、实践验证

我并不反对调研。我反对的是在自己还没有形成任何问题之前，就让调研替自己开始思考。

好的调研应该是对一个初步判断的攻击。它可以帮助我们发现盲点，找到反例，校准方向，把一个抽象的思考收敛成理性的"是/不是"矩阵，也可以让我们意识到自己的问题根本没有被定义清楚。但它不应该在一开始就替我们规定问题是什么。

否则就会出现一种很常见的设计过程：因为别人有某个功能，所以我也要先有这个功能；因为某种风格被很多人喜欢，所以我的产品也应该使用这种风格；因为一个案例被证明成功，所以它就成了我思考的起点。

创作于是变成了盗作。

盗作确实可以让一个零基础的人快速进步。它提供了一条已经被走通的路径，让人暂时拥有一种完成感。但它很难让一个已经有一定基础的人走向优秀。因为你看到的，只是一个事物被切碎之后的符号；再把符号重新拼起来，结果通常只会停留在源头的高度之下。

喷泉永远不会高过它的源头。更何况，我们很多时候连源头为什么要这样流动都没有真正理解。

《把提示词当代码写，还是当爵士弹》里转述过一个研究，读完有种被说穿的感觉："个体变强了，集体变窄了。每个人写出了自己的最佳水平，但大家的最佳水平长得越来越像。" 它讲的是 AI 辅助写作的集体趋同，但我越品越觉得，把别人的案例拼贴进自己产品的人，踩的是同一个坑。

不过这也并非教条式的规则，这种事在大厂之间并不少见：市场已经有了 Trae，却依然容得下 Codebuddy，毕竟背靠丰富资源，足以力大砖飞。

但我还是想重新定义一下"学习"这件事，因为创作的本质与学习在某种层面上是一致的，归结到底就是 I/O，用大家都懂的话说，就是"知行合一"。

模仿 pattern 只能称为"蒸馏"；而从多个 pattern 里总结出规律并能应用，才叫"学习"。

## 高维的点投射出了低维的诸多线面，但投射同样可逆

我越来越相信，借鉴本身并不是问题。问题在于我们借鉴的到底是什么。

世界上很多看起来完全不同的东西，在更宏观的层面上可能拥有相同的结构。游戏设计里的状态机，可以帮助我们理解 Agent 的任务状态；机械系统里的信号传递，可以帮助我们思考复杂工具之间的协作；星际争霸里的编队，也可以成为大型画布中快速组织空间的类比。

这种借鉴不是把外形搬过来，而是发现关系：什么东西被组织起来，什么东西可以被快速调用，状态如何变化，反馈如何传递，用户如何在复杂系统里保持方向感。

大语言模型在这里有时非常有价值。它擅长处理自然语言，能够把很多观点聚类，把复杂长文本压缩成更清晰的结构，也能帮人发现不同领域之间的共同点。但它真正能帮到人的地方，不是替人选择现成的风格，而是帮人看见各种现象背后的相似关系。

## 当"主义"变成一个可以被刻录在光盘上的东西

在设计圈，我们习惯把复杂的现象压缩成几个字：极简主义、功能主义、后现代主义。这样做有很大的沟通价值。一个词可以让同一领域的人迅速对齐语境。

但压缩一定会产生损耗，也会筑起一道理解的城墙——因为即便不懂某个主义的人，也仍能在某次神游里触及主义背后的东西，甚至完全可以再造一个新词来描述它。

同时，当我们越来越依赖这些名词，而不再追溯它们的历史、问题意识和生成过程时，"主义"就开始变成一种包装。它不再是一种对现实的回应，而变成了一套可以被调用的视觉标签。

Agent 和各种 Design Skill 让这件事变得更加明显。现在，我们可以直接说："给我一个苹果风格的网站。"系统很快就会把圆角、留白、字体、毛玻璃和动效组合起来，并且给出一段听起来很完整的设计说明。

这确实让很多人拥有了做出好看界面的能力。但好看的界面之后还有另一个问题：它是否真的理解用户？那些在社区里吹捧前端 Skill、声称自己一天就能做出某某设计的人，或许永远都不会去想：为什么 Apple 的设计能被所有人模仿，也值得所有人认可？

哪怕最细致的风格模板，捕捉到的通常也只是形。它很难回答为什么一个错误提示应该晚几秒出现，为什么某个信息要在此刻隐藏，为什么一个动作需要被打断，另一个动作却应该保持连续。

这些不是教条式的 UX 规则，而是对人的注意力、认知负荷、情感变化和身体习惯的综合判断。它们来自实验、访谈、失败和反复修正，无法被一份 Markdown 文档完整地封装起来。

所以 Skill 降低的是执行成本，不是判断成本。

当执行越来越便宜之后，taste 反而会更清楚地表现为：你把 effort 放在哪里，什么时候停止，什么东西不值得继续做。

## AI Native 提倡用力过猛，却也不提倡用力过猛

我后来发现，Agent 的工作方式里也有同样的问题。

在搭建一个项目的早期，我们很容易先入为主地想很多问题：把模型的 thinking effort 开到最高，打开 plan mode，把上下文提前准备得尽可能完整。我们好像只要把前期想得足够多，后面就能少走弯路。

但很多时候，真实的阻力还没有出现，我们却已经为想象中的阻力准备了大量信息。上下文越长，计划越复杂，行动反而越迟疑。

当然，AI Native 的工作方式并不是 low effort。它更像是用尽可能小的 effort 总量，把 effort 用在真正的刀刃上：先形成一个可以移动的假设，先验证最关键的部分；遇到真实阻力之后，再定向升级搜索、规划、模型或工具。

人仍然需要决定目标、价值和停止条件。AI 可以帮助我们寻找宏观结构、压缩信息、提出几个可能的方向，但它不应该替我们决定哪一个方向值得继续。

## 找回做决策的权利

现在再回头看，我并不认为那次没有调研的大学设计证明了我的天赋。它只是让我看到，人在还没有学会搜索之前，至少还会被迫从问题本身开始思考。

真正需要改变的，不是从此拒绝调研，也不是拒绝借鉴，更不是拒绝 Skill 和 AI。

而是不要让它们在我们还没有形成自己的问题之前，替我们开始思考。

先从原点形成判断，再让世界进入；先找到值得继续的方向，再把 effort 投进去。

> 我们需要的也许不是更多信息，而是重新获得决定信息如何进入自己的权力。

[How Memory Works in Claude Code](https://mem0.ai/blog/how-memory-works-in-claude-code)（In Context #4）— 拆解 Claude Code 的记忆机制：200 行索引、静默截断、后台抽取；也解释了 AGENTS.md 只适合承载不常变化的约定。

[Dream: Background memory consolidation for AI agents](https://mem0.ai/blog/dream-background-memory-consolidation-for-ai-agents) — Mem0 给 Agent 的"睡眠"：合并重复、标记过时、把零散事实归纳成更上层的记忆，且什么都不直接删除。

[Beyond AGENTS.md: Shared Memory for Coding Agents Across Services and Repos](https://mem0.ai/blog/beyond-agents.md-shared-memory-for-coding-agents-across-services-and-repos) — AGENTS.md 回答"这里的规则是什么"，共享记忆回答"从上一次有人看过之后，什么发生了变化"。
