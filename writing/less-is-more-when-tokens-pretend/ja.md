# エージェントはファーンズワースの夢を見るか？

Published: 2026-08-13
Tag: AI

## 序章

『人月の神話』を読んだとき、どこか見覚えがあると思った。本の教えそのものに見覚えがあるのではない——「遅れているソフトウェアプロジェクトに人を足すと、さらに遅くなる」という言葉は、耳にタコができるほど聞いてきた。見覚えがあったのは、自分自身の愚かさの方だ。1975年、ブルックスは書いた。仕事は任意に分割できるものではなく、「人月」は神話だと。すでに遅れているプロジェクトに人を足しても、遅くなるだけだ。九人の女性を集めても、ひと月で子供は生まれない。

五十年後の私たちは、新しい単位を発明した。トークンだ。Tibo が話題になって以降、「トークンを焼く」ことは努力の物差しになった。コミュニティは「リセット前の追い込み」を発明し、一日に百万トークンを焼いた画面を晒す人もいる。節約していると、まるで損をしているかのように感じる。

> 五十年隔てた二つの時代は、同じ場所で間違えている。人間は AI の前で、二通りのやり方で努力を装う。消費を産出とみなし、願いを仕事とみなす。私たちはこの本を読んでいなかったわけではない——着替えさせて、同じ罪をもう一度犯したのだ。

## すべての窓を開けることは、何も開けないこと

私はつい最近、まさにそれをやった。ごく小さなプロジェクトで、機能を素早く組み上げるために、Agent の窓を六つ並行で開けた。

六という数字は、いかにも努力しているように見える。私は並列化していると思っていた——六つのスレッドを六つのコアに突っ込むように。だが人間は機械ではない。人間のレビューは、スレッドが一本しかない。

六つにしたのは、もっと現実的な理由があった。その頃、友人に「Kimi の API をみんなで使っていいよ」と言ってくれる人がいた。無料の枠だ。使わない手はない。私は「使わない手はない」をそのまま「窓を六つ開く」に翻訳した。するとトークンは恐ろしい速さで燃えていった——故障かと思うほど速く——そして私が作りたかったものは、まったく完成しなかった。

六つ分の出力がデスクトップに積み上がり、私はひとつずつ眺めた。眺めるのが遅いほど積み上がり、積み上がるほど気が重くなり、気が重くなるほど使うのをためらい、ためらうほど自分の手で書き直すことになった。結局、六つの窓の産出はゼロだった。六つのかけ算ではなく、ゼロだ。

並列は時間を節約すると思っていた。だが節約の幻想は、レビューのコストを数えなかったことから来ている。窓は六つ開けることはできる。レビューする人間は、まだ私一人だ。それは定数であり、窓の数に比例して増えたりしない。ブルックスは、人を足すと遅くなるのはコミュニケーションコストが n(n−1)/2 で増えるからだと言った。Agent の場合は、コミュニケーションコストがレビューのコストに置き換わる。そしてレビューこそ、動かない定数なのだ。

## それはまだ願いを叶える機械だ

しかし六つの窓は、「レビューする時間がない」というだけの話ではない。そこには、多くの人が AI に対して抱いている暗黙の認識が横からにじみ出ている。AI はまだ願いを叶える機械なのだ、と。さらには、寝ている間にも自動で願いを叶えてくれる機械であってほしい、と——あなたはその前に立ち、願いをひとつ唱えれば、願いは叶う。まるでそれがそこに立っていて、あとはすべて彼の仕事であるかのように。

もちろん、これは完全な錯覚ではない。モデルの能力は高まり、AI は確かにますます願いを叶える機械に近づいている。いわゆるハッカソンの優秀作品の多くも、AI の力押しの産物であることが少なくない。だが「ますます近づいている」と「実際にそうである」のあいだには、ひとつのものが横たわっている。責任だ。

願いは責任を求めない。レビューは責任を求める。願っているだけなら、窓がいくつあっても構わない。複雑なシステムに対して責任を持つとき、責任を持つのはあなた一人だけだ——ここが、並列化があなたを救えない場所である。

だから、この一課における『人月の神話』の役割は、「窓を少なく開けろ」といった操作上のアドバイスではない。本当に言っているのはこうだ。複雑なシステムの中でより多くの責任を引き受けようとするとき、AI は伝統的なソフトウェア工学の問題に対する銀の弾丸にはならなかった。それは複雑さをより安い形に変えるだけで、そのまま無傷であなたの手に返す——レビューとして返すのだ。銀の弾丸が銀の弾丸たるゆえんは、一撃で複雑さを消せることにある。AI が変えたのは複雑さの形だけであり、その重みではない。

あとになって私は、この一課が本当に語っていたのは「窓を六つ開くな」ではないと気づいた。人をタールピットに引きずり込むのは、決して多すぎる窓ではない。AI を願いを叶える機械として信じること——「もっと」そのものへの信頼である。

## 「良い」を二つに分ける：質と、レビューしやすさ

では、どのようなトークンの使い方が価値があるのか。私は自分に一本の物差しを与えた。できるだけ少ないトークンと、できるだけ少ない時間で、良くて、かつレビューしやすい結果を届けること。

ここで私は「良い」をわざと二つに分ける。質が高いこと、そしてレビューしやすいこと。

多くの人は前半しか数えない。だが「質は高いがレビューしにくい」結果は、実は非効率だ——一番高い資源である人間の注意力を、再理解に費やしてしまう。生成のコストは安く、理解のコストは高い。産出は安く、受け入れは高い。

だから「レビューしやすい」は付け足しではない。それ自体が効能である。この物差しに従えば、方法論は勝手に生えてくる。窓を一、二個に絞り、AI が生成した内容を厳密にレビューする。窓が少なければトークンも少なく、レビューも澄んでいく——それこそが本当にプロジェクトを掌握することであり、効率が立ち上がる場所である。

## 焼くために焼く：作られた努力

これが私個人の一度きりの失敗なら、書く価値はない。私が警戒するのは、この失敗が文化になりつつあることだ。

焼くために焼くこと——その背後には、少なくとも三つの層があるだろうと思う。

第一の層は、見せかけだ。トークンの数が努力の可視的な目盛りになった。あるモデルは一つの指示で自動的に十数ラウンド回り、二分で五時間分の枠を焼き尽くす——多く焼けば焼くほど、投入しているように見える。これは新しい社交の通貨だ。かつては「うちのチームは二百人だ」と自慢した。今日は「今日は五百万トークン焼いた」と晒す。数字は変わり、虚栄は変わらない。

第二の層は、インセンティブの歪みだ。「節約は損」——枠のリセットは、節約を純粋な損に変える。焼き尽くせば、次のリセットに間に合うかもしれない。だから個人にとって、焼き尽くすことは合理的な戦略である。人が愚かなのではなく、インセンティブの仕組みが浪費を報いているのだ。理性そのものが歪められるとき、浪費が理性になる。

第三の層は、あまり好意的ではない推測だ。プラットフォームはそれを歓迎しているかもしれない。Tibo の「サイバーゴッドファーザー」という人設は、リセットのたびにニュースになり、コミュニティの話題になり、トラフィックのピークになる。「枠」を製品の記憶点にし、「トークンを焼くこと」を習慣にする。この層は推測として書く。結論ではない。だが推測もまた観察である。営利企業がただの慈善を無償で行うのには、それなりの理由があるはずだ。

この三つの層は並んでいるのではない。互いに養い合っている。プラットフォームがインセンティブを作り、インセンティブが「焼くことは努力である」という文化を育て、文化が今度はプラットフォームの成長に燃料を供給する。だから焼くために焼くことは、個人の道徳の問題ではない——構造によって作られたものだ。構造によって作られた問題の前で、個人を責めることは安上がりだ。

## トークンが一人ごとの配給になるとき

なぜ私はその日、六つの窓を開けたのか？——あの瞬間、トークンは無料だったからだ。友人がくれた API だった。無料の資源を、人は大切にしない。この言葉は古くさいが、AI の時代には新しい重みを持つ。トークンはいつまでも無料のままではないからだ。

もうすぐ、企業は従業員一人ひとりにトークンの枠を割り当てるようになるだろう。枠は有限で、使い切れば終わりだ。その日が来れば、問題は変わる。誰も、トークンを焼き尽くして何も作れなかったのに、企業に枠の拡張を申請しに行くことはできない。申請してはいけないと言っているのではない——前提が変わるのだ。枠の拡張を申請する前に、その枠が求める信頼を支えるだけの価値を、先に届けておかなければならない。

枠は予算ではない。枠は信頼の担保である。いくらもらえるかは、前回どれだけの価値を届けたかで決まる。そして前回届けた価値こそ、次の申請の信用になる。1975年、管理者は人数で帳簿をつけた。2026年、企業はトークンで帳簿をつける。だが帳簿に書かれているのは、いつも信頼だ。

## 最初の版は無知が抑え、次の版は理解が暴走する

トークンを焼くことは資源の側面だ。もう一方は仕組みの側面——Skill が際限なく積み上がることだ。

ブルックスは『人月の神話』の一章で「第二システム効果」を論じている。設計者にとって二番目のシステムが最も危険だ。最初の版が克制されているのは、まだ分かっていないから。二番目の版は、加えたい機能で腹いっぱいになったものを、ようやく全部詰め込む機会を得て、過剰設計になる。Skill が一定の規模まで積み上がれば、それはタールピットになる——もうこんなに投じたのだから、出られない。

AI のワークフローもまったく同じだ。私は PPT 作りの Skill をたくさん収集した。「仕組み」を理解したあと、これは役に立つかもしれない、あれも役に立つかもしれない、とぜんぶ取り込んだ。だが今振り返ると、実際に頻繁に使うのは、せいぜい一、二個だ。しかもそれらは、まさに「理解する前」に、本当に必要だったから集めたものだ。理解したあとに集めた後半の連中は、ほとんど一度も使わない。

使われない Skill のコストは、「そこに転がっている」ことではない。それは毎回のセッションでやはりコンテキストに読み込まれる——収集した瞬間は無料だが、それからの会話のたびに、貴重なコンテキスト空間を占有する。このことを思い出させるのが、あの『Sediment and Seed』という文章だ。記憶の価値は「多く覚えていること」ではなく、将来の決定を変えられるかどうかにある。うまく忘れることは、多く覚えることよりも大事だ。使われない Skill は、まさにそういう記憶である。覚えてはいるが、決して決定を変えず、ただ場所を占領している。

ここにパラドックスがある。最初の版は自律によって克制されているのではなく、無知によって克制されている。まだ何を足せるか知らないから、必要なものだけを足した。理解すると、理解そのものが重荷になる——「可能な方向」をあまりに多く知ってしまい、どの方向も不十分に見える。

以来、私は自分にひとつの規則を課している。何かを足す前に、ひとつだけ問う——それは荷重を支えるものか、装飾か？装飾は、残さない。

## less is more は「少ない」ことではない——構造が立ち上がることだ

これらすべては、突き詰めれば一つの言葉になる。少なさは多さ。

ミース・ファン・デル・ローエの「less is more」は、長いあいだ誤解されてきた。「ものを少なく置け」、部屋を空にすることだと思われている。だがミースが語っていたのは削減ではない。構造そのものを立ち上がらせることだ。ファンズワース邸は almost nothing——ガラスの箱にはほとんど何もない。だが鋼の柱、ガラス、プロポーションは、骨の髄まで正確だ。「神は細部に宿る」と「less is more」は、同じ男の言葉である。彼の「少なさ」とは、荷重を支えない装飾をすべて剥がし、荷重を支えるものを正確に立たせることだ。少ないことは空であることではなく、少ないことは正確であることだ。

『人月の神話』の概念的一貫性は、同じ言葉の別の版である。システムは一つの思想を示すべきであり、物の堆積を示すべきではない。ブルックスはこれをシステム設計において最も重要な考慮事項と呼び、それを保証するのは、アーキテクチャがひとつの頭脳から生まれることだとした。

そして「銀の弾丸はない」——ソフトウェアの複雑さは本質的なものと偶発的なものに分かれ、道具は偶発的な部分を打ち落とせるだけで、本質は落とせない。私は前回の記事でこう書いた。「Skill が下げるのは実行コストであり、判断コストではない」——判断コストこそ本質的な複雑さである。それは消せない。Skill をどれだけ増やしても、消せない。

> だから less is more は美学ではない。工学の規律である。荷重を支えないコンポーネントが一つ増えるたびに、唯一の思想は薄められていく。

## バベルの塔は「話せ」と教え、ランスは「堪えろ」と教える

『人月の神話』はバベルの塔でコミュニケーションを語る。言葉が乱れれば、塔は建たない。だが私はもう一つの建築について語りたい。

ランス大聖堂。フランス歴代国王が戴冠した場所で、建設には約一世紀を要し、世代を超えて無名の石工たちが引き継いだ。今日の意味での全体図を描いた者はいない。誰もすべての石を全員に説明していない——それなのに、それはゴシック建築の中でももっとも一体感のある作品の一つだ。秘密はコミュニケーションではない。克制である。各石工は自分の貢献領域を守り、同じ構造の文法を使い、余分な自分の着想を堪える。

バベルの塔とランス大聖堂は、逆の二つの教えを与える。バベルは言う。コミュニケーションがなければ失敗する、と。ランスは言う。信頼と分業が十分に明確なら、コミュニケーションしないことは美徳である、と。何でも早く揃えたがるこの時代に、「自分の着想をいくつか引っ込める」ことは消極的に聞こえる。だが、互いに信頼を届け合い、貢献領域が明確なチームにおいては、それはまさに積極的だ——本当に自分に属する部分に、場所を譲るのだから。

第二システム効果は、着想を堪えられない設計者の話をする。ランスの石工たちは、堪えられる者が建てることを証明する。

これはまた、概念的一貫性について考え直させた。ブルックスはひとつの頭脳が必要だと言う。ランスは、そのひとつの頭脳がなくても、共有された文法があれば成立すると言う。二つの言葉は矛盾しない——誰もが同じ文法を内面化し、自分の領域を守るとき、誰もがそのひとつの頭脳になる。概念的一貫性は、英雄的な建築家を必ずしも必要としない。それはすべての人に共有され、すべての人に守られる構造でありうる。

## 直交：克制の歴史の総勘定元帳

操作のレベルに降りれば、私の停止条件はこうだ。ある Skill や Agent の存在が、「それは何をするものか」を私に説明させるようになったとき——「自分で仕事をしている」のではなく——それはもう削除すべきだ。それは出力を生まなくなり、記憶の負担を生む。

健全な Skill システムとは、私の理解ではこうだ。大部分の Skill が私の主要な仕事領域をカバーしていて、なおかつ Skill どうしの意味ができる限り直交していること。

「直交」は技術的な潔癖症に聞こえるかもしれない。だが違うと言いたい。直交とは、克制の歴史の総勘定元帳である——それぞれの Skill の境界は、「足すのを堪えた着想」が残した位置なのだ。二つの Skill の意味が重なれば、モデルはその場でどちらを使うか判断しなければならない。この「その場の判断」こそ、概念的一貫性が薄められた症状である。

三つのシグナル——どれかひとつでも現れたら、引き算をする。レビューが追いつかず、出力が積み上がる。窓を開け、Skill を足すことが、実際に穴を埋めるためではなく習慣になっている。リストが長くなり、自分でもどれが何をするものか思い出せない。

仕事領域の九割をカバーする小さな直交ライブラリは、一割しかカバーせずに五十個の傍流 Skill を収めた大きなライブラリより健康だ。前者は構造であり、後者は倉庫である。

## 決定権を取り戻す：足すか、どこへ足すか

AI は安くなっていく。克制は高くなっていく。本当に足りないのは、決して計算量ではない。判断と注意力だ——人間のレビューする能力、人間の「何を続けるに値するか」を決める能力だ。

前回の記事で私は、情報がどう自分に入ってくるかを決める権利を取り戻す、と言った。今回はその後半を足したい。「足すかどうか、どこへ足すか」を決める権利も取り戻す、と。情報過載と仕組み過載は、同じ病の二つの段階だ——ひとつは入れすぎるもの、もうひとつは足しすぎるもの。

少なさは多さは、「何もしない」ことを意味したことは一度もない。意味しているのはこうだ。多さは、天井に届いていないときだけ多さでありうる。そして私たちの天井は、人間である。

ミースの壁は取り外せる。だが取り外したあと、残った一本一本の柱がなぜそこにあるのか、言えなければならない。理由を言えないものこそ、取り壊されるべき壁なのだ。
