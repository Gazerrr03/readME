# 桌面 BOT 文化彩蛋形象调研

> 调研日期：2026-08-11（Asia/Shanghai）  
> 目标：为严格蓝白、直角、1-bit、硬阴影、网格化的 Portfolio OS 寻找一个“桌宠 + 系统助手 + 作者部分人格”的文化原型。优先采用隐约可认出的文化母题，不直接复制已有角色。

## 结论先行

不建议把 BOT 直接画成某个影视或软件角色。这个界面已经有很强的原创系统语言，直接放入 Clippy、HAL、TRON Bit 或某个著名动物轮廓，会让它突然变成“IP 联名皮肤”。更合适的做法是把彩蛋拆成三层：

- **外形母题：**《平面国》的二维几何生命，天然符合方形、蓝白、无圆角的系统。
- **世界观母题：**阿雷西博信息或旅行者金唱片，让它成为凌晨两点仍在收发信号的“小型信使”。
- **行为母题：**oneko 的桌面常驻与跟随、ELIZA 的反问、`Adventure` 的隐藏作者签名、`Daisy Bell` 的极低频声音彩蛋。

最佳结果不是“像某个角色”，而是一个原创的 **Signal Resident / 信号居民**：平时是一枚 24–32px 的空心方形生命，移动时压扁成线，收到消息时内部拼出二进制图样；它偶尔追随光标，但不会持续打扰。懂《平面国》、阿雷西博、早期桌宠或 1979 年 `Adventure` 的人，会分别认出不同层次的彩蛋。

## 评估方法与 IP 边界

美国版权局明确区分“角色的一般概念”和“角色具体的视觉表达”：一般概念不由版权垄断，但足够原创的脸部、身体、服装等视觉特征可能受保护；对已有知名角色做“新版本”也不等于自动安全（[U.S. Copyright Office, Compendium §911](https://www.copyright.gov/comp3/chap900/ch900-visual-art.pdf)）。因此本文的风险等级是设计筛选意见，不是法律结论：

- **低：**原作在美国明确为公版，或软件发行资料明确标为 public domain；仍建议重画，不直接搬运某一现代版本的素材。
- **中：**概念或官方素材较开放，但具体图、录音、标志或后续改编仍可能另有权利。
- **高：**活跃商业 IP 的著名角色；只借交互原则，不借名称、轮廓、脸、台词和标志性动画。

## 12 个候选详解

### 1. 《平面国》：A Square

- **原始出处：**Edwin A. Abbott 的 1884 年《Flatland》。原文把世界描述成“线、三角形、方形等在平面上自由移动”，叙述者署名 `A SQUARE`；Project Gutenberg 标注该书在美国为公版（[原文](https://www.gutenberg.org/files/45506/45506-h/45506-h.htm)，[版权状态](https://www.gutenberg.org/ebooks/201)）。
- **意义与语气：**一个只能理解二维世界的居民短暂看见更高维度，主题是视角限制、好奇心和对未知的谦逊。它很适合替作者接待访客：不是全知 AI，而是这个系统里的本地居民。
- **可转译的视觉：**空心方框；一只眼不是画出来，而是某个角点闪烁；侧身时压成一条线；打开窗口时短暂“升维”为线框立方体，再退回二维。
- **可转译的行为：**状态码可写成 `DIMENSION: 2`、`VIEW: EDGE`、`SPACELAND SIGNAL RECEIVED`；讲项目时像从系统内部向外解释。
- **识别度 / 适配：**大众识别度中等，但文学、数学、设计受众会很快意识到彩蛋；与直角、蓝白、网格、1-bit 的适配几乎无损。
- **IP 风险：低。**采用几何生命和升维概念即可；不要照搬某个现代电影/插画版的具体脸和服装。

### 2. 阿雷西博信息：1679 个 bit 的信使

- **原始出处：**1974 年阿雷西博望远镜向 M13 发送了一段图像信息。SETI Institute 记载它由 `1679` 个 bit 组成，可排成 `73 × 23`，以每秒 10 bit 发送，总时长不到三分钟，内容包括望远镜、太阳系、DNA、人形与生命化学信息（[SETI Institute](https://www.seti.org/research/seti-101/project-phoenix/arecibo/)）。
- **意义与语气：**不是请求即时回复，而是在巨大时间尺度里证明“这里曾有人试图介绍自己”。这与个人作品集本质很接近：把自己的信号发给未知访客。
- **可转译的视觉：**一个由少量方格构成的“未完成图形”；说话时内部 bit 逐列点亮；背部有 23 格短条；不复制完整原始图，而是生成自己的作者数据包。
- **可转译的行为：**首次出现显示 `PACKET 1679 / DECODED`；长时间无人操作时朝屏幕边缘发送一次 3 帧短脉冲；访客打开 About 后，BOT 才完成“人形”或作者 monogram。
- **识别度 / 适配：**大众中等，科技受众高；“信号 + bit + 网格”与当前界面完全同源。
- **IP 风险：低–中。**历史事实和编码原则可作母题，但建议重新编码作者自己的信息，不直接把官方示意图当角色贴图。

### 3. Atari `Adventure`：会找到秘密作者房间的小方块

- **原始出处：**创作者 Warren Robinett 的项目页记载，1979 年 Atari 2600 游戏 `Adventure` 的玩家在大型多屏世界中搬动物品；游戏藏有一个秘密房间，里面是作者签名，他称其为首个电子游戏 Easter Egg（[Warren Robinett 本人页面](http://www.warrenrobinett.com/adventure/index.html)）。页面还记录游戏仅使用 4KB ROM 与 128 bytes RAM。
- **意义与语气：**这不是“引用一个角色”，而是引用“作者在系统里偷偷留下自己”的行为，尤其适合 portfolio。
- **可转译的视觉：**BOT 保持极简 8×8 或 12×12 方块；携带文件时身旁多一个小图标；偶尔从窗口边框的 1px 缝隙穿过。
- **可转译的行为：**连续完成某组浏览动作后，它带访客进入一个隐藏的 `CREATOR ROOM`，只展示作者签名、build 编号或一段私密注释；不要复刻城堡、钥匙、龙和原地图。
- **识别度 / 适配：**一般访客会理解为站内秘密；熟悉游戏史的人会认出更深一层。方块玩家与当前 1-bit OS 高度适配。
- **IP 风险：低–中。**只采用“极小玩家方块 + 隐藏作者房间”这一机制，并使用原创关卡与图形；不使用 Atari 名称、原 ROM、角色或地图素材。

### 4. oneko / xneko：追随光标的早期桌宠

- **原始出处：**Debian 的版权清单说明原始 xneko 由 Masayuki Koba 编写，Tatsuya Kato 将其改为 oneko，并记录原 README 与 LSM 均称 oneko 为 public-domain software（[Debian Source Package](https://tracker.debian.org/media/packages/o/oneko/copyright-1.2.sakura.6-16)）。原始发行说明把功能概括为一只小猫在工作时追逐鼠标光标（[原始 README 镜像](http://www.daidouji.com/oneko/distfiles/README)）。
- **意义与语气：**它提供的是“桌面里确实住着一个小东西”的行为记忆，而不是聊天浮窗。
- **可转译的视觉：**不要再画一只猫；改成两足或四足的方块“数据包”，用 3–4 帧步态，停下后折叠成系统图标。
- **可转译的行为：**只在用户快速甩动光标或主动呼唤时追随；到达后坐下/收起，而不是永远追着跑。窗口打开时沿窗口外缘绕行，绝不盖住控件。
- **识别度 / 适配：**Unix、早期网页和桌宠爱好者识别度高；普通访客也能立即理解。
- **IP 风险：低。**发行记录明确为 public domain；为了保持原创品牌，仍建议只借行为史，不复用原 bitmap。

### 5. 康威生命游戏：glider 作为“活着的像素”

- **原始出处：**Martin Gardner 在 1970 年 10 月的 `Scientific American` “Mathematical Games”专栏介绍了 John Conway 的 Life（[原始专栏页面](https://www.scientificamerican.com/article/mathematical-games-1970-10/)）；规则是在网格上让细胞按邻居数量出生或死亡（[交互规则页](https://playgameoflife.com/)）。
- **意义与语气：**极少的二值规则可以产生看起来“有生命”的移动结构。BOT 因此可以是系统状态的涌现物，而不是被贴上去的吉祥物。
- **可转译的视觉：**以经典五格移动结构为待机核心，但在角色状态中加入原创外框或尾迹；移动严格按格跳，不做平滑漂浮。
- **可转译的行为：**系统忙碌时分裂为若干 cell，完成后重新合并；减少动态模式下直接显示最终组合状态。
- **识别度 / 适配：**程序员识别度很高；二值、网格、`steps()` 动画完全契合现有规范。
- **IP 风险：低。**生命游戏的规则和操作方法属于“思想/方法”层，版权局明确指出版权不保护思想、方法或系统本身（[U.S. Copyright Office](https://www.copyright.gov/comp3/chap900/ch900-visual-art.pdf)）；具体网站素材或说明文字仍不应直接搬用。

### 6. 旅行者金唱片：替人类保存问候的记录员

- **原始出处：**NASA 把旅行者金唱片描述为一张 12 英寸镀金铜盘，包含旨在呈现地球生命与文化多样性的图像、声音、音乐与 55 种语言问候，是给可能遇见飞船的未知文明的“时间胶囊”（[NASA Golden Record Overview](https://science.nasa.gov/mission/voyager/voyager-golden-record-overview/)，[55 种语言问候](https://science.nasa.gov/mission/voyager/golden-record-contents/greetings/)）。
- **意义与语气：**它比“聪明助手”更有人味：主要职责不是给答案，而是把人类的痕迹妥善带走。
- **可转译的视觉：**小型探针 / 记录盒、折叠天线、同心方框波纹；不要做金色，也不要复制唱片封套图，保持蓝白。
- **可转译的行为：**按站点语言保存不同问候；浏览过的项目成为它携带的 `RECORD 01/04`；离开页面时发出一句简短的本地化 goodbye。
- **识别度 / 适配：**识别度高，文学气质也足；圆盘母题需要方形化处理后才完全融入 UI。
- **IP 风险：低–中。**NASA 说明其内容通常不受美国版权约束，但 NASA 标志与识别资产不属于公版，且网站可能含第三方版权材料（[NASA Media Guidelines](https://www.nasa.gov/nasa-brand-center/images-and-media/)）。因此只借任务和结构，不用 NASA 标志，也不复制唱片内受权利保护的音乐、照片或录音。

### 7. ELIZA：会倾听、会反问，但不装作全知

- **原始出处：**Joseph Weizenbaum 在 1966 年发表 `ELIZA—A Computer Program for the Study of Natural Language Communication Between Man and Machine`，论文与 DOI 可在 ACM 查阅（[ACM DOI 10.1145/365153.365168](https://dl.acm.org/doi/10.1145/365153.365168)）。
- **意义与语气：**ELIZA 的文化意义不在“像人”，而在于极少的语言机制也会让人主动投射人格。对 portfolio BOT 来说，这是一条很好的克制原则。
- **可转译的视觉：**角色本体只是一条插入光标或会开合的括号；对话气泡像系统日志，不画人脸。
- **可转译的行为：**先复述访客句子中的关键词，再给项目入口；不知道就明确说不知道；偶尔用反问把对话交还给用户。
- **识别度 / 适配：**AI 史受众识别度高；纯文本视觉适配很好，但单独使用时“宠物感”较弱。
- **IP 风险：低–中。**可以借“反射式对话”的交互原则；不要复制原始 DOCTOR 脚本、连续台词或把产品直接命名为 ELIZA。

### 8. `Daisy Bell`：机器第一次唱歌的幽灵

- **原始出处：**美国国会图书馆记录，Bell Labs 的 John L. Kelly Jr.、Carol Lochbaum 和 Max Mathews 在 1961 年让 IBM 704 演唱 `Daisy Bell`；该录音被收入 National Recording Registry，并影响了 `2001: A Space Odyssey` 中 HAL 的退场（[Library of Congress 2009 Registry](https://www.loc.gov/programs/national-recording-preservation-board/recording-registry/registry-by-induction-years/2009/)，[扩展论文](https://www.loc.gov/static/programs/national-recording-preservation-board/documents/DaisyBell.pdf)）。歌曲本身写于 1892 年，但 1961 年录音是独立的历史录音。
- **意义与语气：**它同时可爱、脆弱、轻微不安；很适合只被极少数人撞见的“机器有记忆”彩蛋。
- **可转译的视觉：**两只相扣的方形轮、8 段波形、打孔卡节奏；不要画花，也不需要出现 HAL 的红色镜头。
- **可转译的行为：**在凌晨 2:00、低音量开启且用户连续空闲一段时间后，只播放原创合成的 2–4 个音；点击后显示 `VOICE TEST / 1961`，而不是完整演唱。
- **识别度 / 适配：**计算史和电影受众会认出，其他人只会感到一个略诡异的声音细节。
- **IP 风险：低–中。**可重新演奏古老旋律，但不要采样 1961 年 Bell Labs 录音，也不要复刻电影中 HAL 的具体表演、台词和音色。

### 9. Edgar Allan Poe《乌鸦》：午夜访客与单词回答

- **原始出处：**《The Raven》开篇是“午夜沉闷”与房门上的轻敲，访客最终停在门上方，只回答 `Nevermore`；Project Gutenberg 标注文本在美国为公版（[原文](https://www.gutenberg.org/files/1065/1065-h/1065-h.htm)，[版权状态](https://www.gutenberg.org/ebooks/1065)）。
- **意义与语气：**这是最直接的凌晨两点文学彩蛋：安静的陪伴、轻微神秘、固定的干式回应。
- **可转译的视觉：**不要做写实鸟或引用影视版；用一个由 5–7 个矩形组成、像折叠信号旗的黑蓝剪影，停在窗口标题栏外侧。
- **可转译的行为：**出现前敲三下；面对无效命令只回一个原创系统词，例如 `UNRESOLVED`，避免把 `Nevermore` 当口头禅用到厌烦。
- **识别度 / 适配：**识别度高，气氛适配高；但若轮廓太具象，会让整体从“系统”偏向“哥特文学主题”。
- **IP 风险：低。**原诗公版；仍不要复制现代电影、游戏或插画中的特定乌鸦造型。

### 10. Plan 9 的 Glenda：操作系统真的有一个居民

- **原始出处：**Plan 9 官方站说明 Glenda 是 Renée French 绘制的 Plan 9 兔子，并提供不同分辨率图像；页面允许用图制作 T-shirt 等物品，但页脚仍标注 Plan 9 Foundation 版权（[Plan 9 / Glenda](https://9p.io/plan9/glenda.html)）。
- **意义与语气：**它说明一个严肃操作系统也可以有一只很小、很个人化的居民，且不必把整个界面变得儿童化。
- **可转译的视觉：**只借“小型 OS resident + 黑白反相”这个结构，不借兔耳、脸型、坐姿或名字；角色应从 Portfolio OS 的网格与协议符号长出来。
- **可转译的行为：**启动时像服务进程出现；关于页里藏一行 `resident process`; 可作为 Window/macOS 两种桌面的共享服务。
- **识别度 / 适配：**普通人低，Unix / Plan 9 文化人群高；作为小众彩蛋很有效。
- **IP 风险：中。**官方页面对部分实物使用给了宽松表达，但不是通用的品牌授权；不要直接把 Glenda 图像当作品集 mascot。

### 11. Office Assistant / Clippy：应当继承教训，而非轮廓

- **原始出处：**微软旧版 Office 开发文档把 Assistant 描述为一次只能激活一个的常驻对象，支持显示、启用和 greeting 等动画；Office 2007 文档明确标注 Assistant 已弃用（[Microsoft Learn: Assistant Object](https://learn.microsoft.com/en-us/previous-versions/office/developer/office-2007/aa432065%28v=office.12%29)）。微软自己的 UI 历史文章称它更像“上下文帮助实验”，并提到用户会右键观看其动画（[Microsoft Archive](https://learn.microsoft.com/en-us/archive/blogs/jensenh/new-rectangles-to-the-rescue-why-the-ui-part-4-2)）。
- **意义与语气：**它的价值是提醒设计者：BOT 必须可关闭、可忽略、只在有上下文时出现，且不能挡住任务。
- **可转译的视觉：**不使用回形针、两只眼、白色金属身体或经典弹跳；只继承“常驻单实例”和小段 greeting 动画。
- **可转译的行为：**默认被动；用户完成一次真实任务后才给一条建议；设置中有明确的 `BOT: OFF / QUIET / ACTIVE`。
- **识别度 / 适配：**识别度极高，但原造型的圆弧与当前直角系统冲突。
- **IP 风险：高。**微软把名称、图标、设计、trade dress 等列为专有品牌资产，许多设计用途需先获许可（[Microsoft Trademark and Brand Guidelines](https://www.microsoft.com/en-us/legal/intellectualproperty/trademarks)）。不要做“蓝色像素 Clippy”。

### 12. `TRON` 的 Bit：概念完美，直接画出来却最危险

- **原始出处：**Disney 的官方电影页把 1982 年 `TRON` 描述为 Flynn 被传送进数字世界、成为自己游戏一部分的故事（[Disney Movies: TRON](https://movies.disney.com/tron)）。影片中的 Bit 以抽象几何体表达二值 `YES / NO`，与本项目的蓝白开关语言高度相似。
- **意义与语气：**它是“系统中的最小生命单元”，用形状状态而不是面部表情交流。
- **可转译的视觉：**只借“不同状态对应不同几何构型”；角色保持方形或不规则像素团，不用 Bit 的多面体轮廓、红蓝配色和 `YES/NO` 声音。
- **可转译的行为：**用 `ACK / NAK`、`0 / 1` 或实心 / 空心切换表达肯定与否定；动画按格切换而非旋转发光。
- **识别度 / 适配：**识别度高、主题适配高，但太接近时会立刻被看作 TRON 衍生角色。
- **IP 风险：高。**Disney 明确表示其电影、角色、图像、艺术品等是 Disney 或授权方的版权 / 商标资产，营销或品牌用途通常不在消费者许可内（[Disney Terms of Use](https://disneytermsofuse.com/english/)）。只保留抽象的二值沟通原则。

## 三个终选方案

### A. `SIGNAL SQUARE` / 信号方格（首选）

**参考叠层：**《平面国》外形 + 阿雷西博世界观 + `Adventure` 隐藏作者房间。

- 本体是 `24 × 24px` 空心方形，内部有 `5 × 5` 可亮灭 cell；唯一的“脸”是一个会换角的像素点。
- 静止时像桌面图标；移动时侧身压成线；唤醒时短暂变成立方体线框，然后掉回二维。
- 它自称这个 OS 的 `LOCAL RESIDENT`，不自称作者本人；讲项目时偶尔说“从系统内部看……”。
- `1679` 作为 build / packet 编号隐藏在 About 或启动日志里；完成特定浏览路径后，它从 1px 边缝钻入 `CREATOR ROOM`。
- 优点：原创度最高、与现有 UI 几乎零冲突、文学与科技彩蛋可以同时存在。缺点：宠物感需要靠步态和反应补足。

### B. `PACKET RUNNER` / 数据包跑者

**参考叠层：**oneko 行为 + 康威 glider 动画 + ELIZA 对话。

- 本体不是动物，而是一组 5–9 个蓝色像素 cell；奔跑时像四足小物，停下后自动排列成 glider / 光标 / 信封三种系统符号。
- 用户快速移动鼠标后它追随一次，到达即停止；用户选中文字时，它像在“闻”一个数据包，但不弹提示。
- 对话永远先复述关键词，再给一个入口；不知道就显示 `NO LOCAL RECORD`，不装作全知。
- 优点：桌宠感最强、懂早期桌宠的人会心一笑、仍保持抽象原创。缺点：像素重排需要仔细做可读性和 reduced-motion 版本。

### C. `RECORD KEEPER` / 夜间记录员

**参考叠层：**旅行者金唱片人格 + `Daisy Bell` 声音记忆 + 《乌鸦》的午夜到访。

- 本体是一个方形记录盒，侧面伸出折线天线；停在窗口标题栏或桌面边缘，像一个值夜服务。
- 它把访客打开过的作品记为 `RECORD 01/04`，离开前用当前语言发一句简短问候。
- 午夜后才会出现三次微弱敲击；非常低概率触发 2–4 个原创合成音和 `VOICE TEST / 1961`。
- 优点：情感最强、最贴合“凌晨两点的神秘信号”。缺点：视觉不如前两案天然像“活物”，声音必须默认关闭或极克制。

## 推荐组合与明确禁区

如果只做一个方向，选 **A：SIGNAL SQUARE**。如果希望更像桌宠，把 B 的“被呼唤才追随一次”和 cell 步态加进 A；如果希望它更有作者气质，把 C 的记录行为和多语言 goodbye 加进 A。这样最后仍然是一个角色，而不是三种角色拼贴。

建议的最终配方：

| 层级 | 采用来源 | 落地方式 |
| --- | --- | --- |
| 轮廓 | 《平面国》 | 方形 / 线 / 短暂立方体三态 |
| 材质 | 阿雷西博 + Life | 内部二值 cell 与离散重排 |
| 移动 | oneko | 受邀追随一次，随后收起 |
| 对话 | ELIZA | 复述关键词、承认未知、短句 |
| 站内秘密 | `Adventure` | 作者签名房间 / build 号 |
| 情感彩蛋 | Voyager + `Daisy Bell` | 保存问候；极低频声音测试 |

明确不要做：

- 不要回形针身体、两只大眼睛、弹簧式跳动或“看起来你正在……”文案。
- 不要红色圆形镜头、TRON 多面体、兔耳、现成 oneko bitmap 或任何现代改编版角色轮廓。
- 不要持续追鼠标、自动开口、遮挡窗口、循环叫声或需要访客理解出处才能操作的核心功能。
- 彩蛋应当是“认出来会多一层快乐”，而不是角色可用性的前置知识。

## 需要向作者确认的 6 个问题

1. 你希望熟人一眼认出是“你”，还是只在说话方式里感觉像你？这决定 BOT 是否需要头像 / monogram。
2. 你更偏爱哪种彩蛋受众：文学读者、科幻电影观众、程序员 / 黑客文化，还是 2000 年前后的互联网用户？
3. 你对“抽象几何生命”的接受度如何？如果必须有明确生物轮廓，A 需要增加肢体，B 会更合适。
4. BOT 可以多主动：完全被动、偶尔看向光标、受邀后跟随，还是会自己探索桌面？
5. 你能接受轻微诡异感吗，例如午夜敲击、单词回答和 1961 电脑声；还是必须始终友善温暖？
6. 你有哪些只属于自己的小物件、习惯、口头禅或创作符号？最终至少应有一个私人特征压过文化引用，否则仍可能像“聪明的同人设计”。
