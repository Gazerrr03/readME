# 无标题《戚风主义》ASCII 桌面环境设计

Date: 2026-08-15  
Status: Review requested

## 1. 目标

把现有桌面环境从 Yorushika 封面派生的 ASCII 地形，转成一张无标题、蓝底白色结构的太空专辑封面抽象。视觉参考是相对性理论《戚风主义》的封面构图，但运行时不复制参考图中的播放器界面，也不引入任何标题或说明文字。

本次只切换视觉主题。`media/catalog.js`、本地音频、音乐卡片的播放/暂停、切歌和随机播放逻辑都保持不变。macOS 界面是主要视觉验收目标；现有 Windows 和窄屏行为不能被破坏。

## 2. 已确认的设计边界

### 包含

- 蓝色桌面场景和白色 ASCII 结构。
- 左上稀疏圆球、中部可辨认的漂浮宇航员、右下斜向地球弧线。
- 宇航员沿水平方向周期性缓慢位移。
- 企鹅 hover 时短暂出现由线稿、点阵、像素块和横向切片组成的故障效果。
- `prefers-reduced-motion`、窗口聚焦和窄屏静态降级。
- 保留 Pen Pen 的现有形象、`PEN²` 识别点和现有桌宠交互。

### 不包含

- `シフォン主義`、`相対性理論` 或任何新增标题、艺术家名、说明文字。
- 建筑、蓝图网格或 Farnsworth House 视觉元素。
- 右侧播放器 UI、红色播放按钮或参考图中的元数据面板。
- 替换真实音频、曲目数据或音乐播放器交互。
- 持续的强烈故障、镜头抖动、光标跟随光斑或粒子拖尾。
- Windows 专属背景重做。

## 3. 视觉设计

### 3.1 构图

桌面仍使用现有 `--environment-blue` 和白色墨线系统。画面采用大面积负空间，三处元素构成类似专辑封面的识别骨架：

1. 左上区域放置一个低密度点阵圆球，作为月球/舞会球的抽象来源。
2. 中部偏左放置宇航员。头盔、躯干、四肢和漂浮姿态必须保持为可辨认的人形；ASCII 只改变边缘和明暗，不把主体打散成随机字符。
3. 右下区域放置一条从画面边缘切入的地球弧线。弧线只保留少量横向纹理，不绘制完整地球或照片细节。

圆球和地球弧线是陪衬，宇航员是唯一的主要视觉主体。画面不依赖文字完成识别。

### 3.2 ASCII 语言

场景使用有限的单色字符密度，不使用彩色字符。高密度字符用于宇航员轮廓和圆球局部，低密度字符用于环境噪声和地球弧线。字符密度由结构化场景数据控制，而不是直接把一张照片整体转换成字符。

场景数据应包含可独立定位的 `sphere`、`astronaut` 和 `earthArc` 三个组件。这样宇航员可以移动，而其他元素不需要跟着移动；也便于单元测试和后续微调。

### 3.3 安静区域

现有桌面组件、Dock、菜单栏和窗口周围的 quiet zone 规则继续有效。ASCII 结构在这些区域逐渐稀疏，不出现矩形遮罩或玻璃面板。桌宠所在的右下区域保留足够负空间，避免地球弧线与 Pen Pen 发生视觉粘连。

## 4. 动效与交互

### 4.1 背景运动

把背景理解成三张透明薄片：稳定的蓝色底、稳定的陪衬结构、缓慢运动的宇航员层。

- `running` 状态下，宇航员只做 X 轴方向的缓慢往返运动。
- 运动周期约 18–24 秒，使用平滑的正弦式往返，不突然加速、不弹跳。
- 位移随视口缩放，桌面端约 12–24px；不改变宇航员的人形比例。
- 宇航员不做持续旋转或上下漂浮，避免变成动态壁纸。
- 圆球和地球弧线保持稳定；只允许很轻的字符闪烁或扫描变化作为次级生命感。
- 现有窗口聚焦状态继续冻结当前完整画面，并保留现有 Canvas 降低透明度的处理。
- `static` 状态和 `prefers-reduced-motion: reduce` 下宇航员停在中性位置，不启动动画循环。

背景的主要动效是宇航员运动，鼠标不再引入新的强视觉效果。

### 4.2 企鹅 hover 故障

企鹅仍使用当前 spritesheet 和现有 `waving` 状态。指针从外部进入 Pen Pen 的按钮区域时，在不改变主体形象的前提下触发一次短暂 glitch：

- 故障层只存在约 240–420ms，然后自动清除。
- 每次 hover 只显示一种主要结构，避免点阵、像素块和扫描线同时堆叠。
- 结构来源限定为参考图中已经确认的视觉语法：轮廓线、点阵、像素块、横向波纹/切片。
- 故障层沿企鹅轮廓局部错位，不生成新的角色、不显示标题、不覆盖 `PEN²` 识别点。
- 指针离开后不留下残影；再次进入时可以重新触发。
- 粗指针设备、键盘操作和 reduced-motion 模式不触发移动故障层。

故障效果是桌宠的隐藏彩蛋，不是背景的常驻装饰。现有 hover 上移和 waving 行为继续保留。

## 5. 架构与数据流

### 5.1 场景数据

新增一个本地、无网络依赖的场景数据模块，例如 `scripts/environment/qifeng-scene.js`。它提供：

- 场景标识和蓝/白颜色令牌引用。
- 三个视觉组件的归一化位置、尺寸和字符/点阵掩码。
- 用于圆球、宇航员和地球弧线的稳定几何信息。

运行时不读取参考图，不依赖外部图片请求，也不把标题文字作为图像资产。可使用图像生成做构图草图，但最终接入的是可维护的本地结构化数据。

现有 Yorushika `JACKET_MAP` 不再作为桌面环境的运行时输入。旧的生成脚本和来源文件不在本次范围内删除，以免把视觉替换和历史素材清理混在一起；运行时只应切换到新的无标题场景数据。

### 5.2 Renderer

`createEnvironmentRenderer` 继续负责 Canvas 生命周期、尺寸、DPR、motion state 和 quiet zones。它新增对结构化场景的绘制：

- 先绘制蓝色底层。
- 再绘制稳定的圆球和地球弧线。
- 最后绘制带 X 轴相位的宇航员层。
- `running` 只更新场景时间和必要的字符扫描；`focused`、`static` 和销毁状态停止调度。

Renderer 不查询桌宠 DOM、音乐数据或窗口内容。桌面环境 controller 仍然只负责把当前环境状态传给 renderer。

### 5.3 Desktop controller 与桌宠

`environment-controller.js` 将 renderer 的输入从旧的 `JACKET_MAP` 切换为新的场景对象，保留现有 capability、窗口聚焦、响应式和 reduced-motion 状态机。

`desktop.js` 继续拥有 Pen Pen 的 hover 事件和 spritesheet 状态。glitch 使用独立的装饰层或数据属性，不改变现有按钮语义、可访问名称和 `PEN²` 图像资产。

音乐 deck 仍从 `media/catalog.js` 读取现有 `tracks`。本次不修改曲目标题、音频文件、音频状态或 Albums 页面。

## 6. 响应式与无障碍

- macOS 宽屏细指针：显示完整场景和宇航员缓慢运动。
- 平板、粗指针设备和窄屏：沿用现有静态简化环境规则；宇航员保持可辨认但不移动。
- 手机：沿用现有 background-only 静态 fallback，不增加新的交互层。
- Windows：保留现有挂载和功能行为，不做专属视觉重构。
- reduced-motion：背景静态，企鹅不触发移动 glitch，但保留按钮点击、键盘焦点和现有 waving 之外的可用功能。
- Canvas 继续使用 `aria-hidden="true"`；glitch 层为装饰，不增加重复的辅助技术文本。
- 颜色和对比度继续使用现有蓝/白系统；不以闪烁、快速切片或颜色变化传达唯一信息。

## 7. 错误处理

- 场景数据无效时，renderer 回退到蓝色底和最小的几何圆球、宇航员轮廓、地球弧线。
- Canvas 初始化失败时，保留现有 HTML widgets、桌宠、Dock、菜单栏和窗口功能。
- 场景数据加载或尺寸计算失败不能阻塞音频 deck 和应用启动。
- glitch 装饰层创建失败时，Pen Pen 仍保持现有 spritesheet、hover waving 和点击行为。

## 8. 验收标准

### 视觉

- 在 macOS 桌面默认尺寸下，不依靠文字也能看出“蓝底 ASCII 太空封面”。
- 宇航员在静态截图中保持清晰人形，不被字符噪声吞没。
- 左上圆球、中心宇航员、右下地球弧线的空间关系稳定，负空间明显。
- 宇航员的左右运动能被观察到，但不会像屏保一样抢夺注意力。
- 企鹅仍位于右下角，`PEN²` 仍可识别；hover glitch 短暂、克制、可重复触发。
- 画面中没有新增标题、艺术家名或播放器 UI。

### 行为与回归

- 现有音频 deck 的三首本地曲目、播放/暂停、下一曲和状态文本不变。
- 背景在 running 状态会随时间变化，在 focused 状态冻结，在 reduced-motion 和静态 fallback 下不启动动画循环。
- 企鹅 hover 保留 waving 状态；glitch 清理后 DOM 和视觉状态恢复。
- Windows、平板、手机和 Dock/窗口 quiet zone 不发生回归。
- 单元测试覆盖场景数据形状、宇航员随时间位移、静态/聚焦冻结和销毁清理。
- E2E 覆盖无标题场景、macOS 视觉截图、桌宠 hover glitch、reduced-motion 和现有音乐 deck 回归。

## 9. 实施边界

实施顺序应为：先接入无标题场景并完成静态视觉验收，再加入宇航员慢速位移，最后接入企鹅 glitch。任何一步都不应修改 `media/catalog.js` 或音频文件。若视觉截图显示宇航员不够可辨认，优先调整场景掩码和字符密度，不增加标题或额外 UI。
