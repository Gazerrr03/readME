# Portfolio OS UI Kit 重构设计规格

> 状态：待用户审阅
> 日期：2026-08-15
> 设计基线：B / Deep Indigo
> 系统壳层：Shell 2 / Two Platform Skins
> 桌面密度：Density 2 / Workstation Desktop
> 组件表面：Surface 2 / Retro Hardware

## 1. 目标与问题

### 1.1 目标

将当前由 blueprint、蓝调像素背景和桌面窗口逐步拼接出来的界面，重构为一套可持续扩展的、自有识别度明确的 Portfolio OS UI Kit。

这套 UI Kit 应该让访客产生三个连续判断：

1. 这是一个可以操作的个人操作系统，而不是带有桌面装饰的普通作品集。
2. 这个系统的窗口、按钮、菜单、状态和应用属于同一个设计家族。
3. 它借用了复古计算机和像素显示设备的记忆，但不是某个真实操作系统的仿制品。

### 1.2 当前问题

- blueprint 时期的网格、扫描线、点阵、硬阴影和技术图纸语法仍散落在全局样式中。
- 后期加入的桌面栏、窗口、Dock、图标和 Pen Pen 没有共享完整的组件状态规则。
- macOS 与 Windows 的壳层已经存在，但视觉边界和组件来源不够清楚。
- 背景、系统对象、应用内容和前景彩蛋之间有过度耦合的历史痕迹。
- design.md 已记录蓝调像素背景，但还没有覆盖本次确定的完整 OS UI Kit。

## 2. 已确认的设计决策

| 决策 | 选择 | 设计含义 |
| --- | --- | --- |
| 色彩基线 | B / Deep Indigo | 深海军蓝作为系统底色，靛蓝作为主要强调色，浅蓝白作为高亮和文字 |
| 系统壳层 | Shell 2 / Two Platform Skins | macOS 与 Windows 保留各自系统 chrome；窗口、控件和状态语义来自同一套基础组件 |
| 桌面密度 | Density 2 / Workstation Desktop | 桌面常驻有限的状态、快捷入口和信息面板，接近个人工作站而非纯展示页 |
| 组件表面 | Surface 2 / Retro Hardware | 使用克制的凸起、凹陷、渐变和按压反馈，建立实体设备般的操作感 |
| 主要平台 | macOS 优先 | 以 macOS 视图作为第一验收基准，再补齐 Windows 壳层差异 |
| 背景策略 | 预处理像素图片 / GIF | 背景是素材，不再由运行时 ASCII、Canvas 扰动或鼠标水波生成 |
| 前景彩蛋 | 白色 Pen Pen | 保留可识别的 PEN² 细节，作为独立前景对象，不合并进背景 |

### 2.1 组合后的产品气质

这不是“复古效果越多越好”的方向。最终气质应当是：

> 一台在夜间运行的个人工作站：有旧硬件的触感，有像素显示设备的限制，也有现代软件清晰的状态反馈。

## 3. 非目标

本次重构不包含以下内容：

- 不复制 macOS、Windows 或某个 Linux 桌面的完整品牌外观。
- 不把所有页面做成同一种终端窗口，也不把所有内容改成像素字体。
- 不重新引入 blueprint 网格作为默认背景主题。
- 不重新引入运行时 ASCII 字符背景、鼠标水波、实时 Canvas 扰动或无意义粒子。
- 不为每个应用创建独立品牌色或独立组件套件。
- 不在首屏加入营销型 Hero、功能卖点或解释性长文案。
- 不在本阶段改变音频内容、文章内容模型或项目内容本身。
- 不先重做 Pen Pen 素材；先完成它在新系统中的层级、状态和交互契约。

## 4. 视觉基础

### 4.1 色彩令牌

以下是实现阶段的第一版候选令牌。它们用于建立层级，最终值可以在视觉验收时做小幅校准，但不能改变色彩关系。

~~~css
--os-canvas: #071426;
--os-surface: #0E2340;
--os-surface-raised: #1A2E46;
--os-surface-highlight: #40566A;
--os-accent: #748BFF;
--os-accent-bright: #B9D7FF;
--os-ink: #F2F6FF;
--os-muted: #8296B8;
--os-shadow: #020811;
~~~

使用规则：

- canvas 只用于桌面底色和深层工作区。
- surface 用于窗口、系统栏和普通面板。
- surface-raised 用于标题栏、被抬高的工具条和工作站面板。
- surface-highlight 用于边缘高光、分隔和硬件表面渐变的中间色。
- accent 用于当前选中、主操作和活动状态。
- accent-bright 用于焦点边框、按钮高光和少量像素高亮。
- ink 用于主要文字和关键图形。
- muted 用于次要文字、非活动状态和信息密度较低的元数据。
- shadow 只作为不透明或近不透明的硬阴影，不做模糊阴影。

禁止：

- 为不同应用分配不同主色。
- 使用霓虹发光、彩虹渐变或大面积透明玻璃效果。
- 使用低对比度透明文字制造“氛围”。
- 把背景图片中的颜色直接扩散成新的 UI 令牌。

### 4.2 Retro Hardware 表面语言

组件不采用纯平的现代卡片，也不采用厚重的拟物 UI。表面语言遵守以下范围：

- 普通窗口：1px 外边框 + 1px 内部高光 + 4px 左下硬阴影。
- 活动窗口：提高边框和阴影对比度，但不增加模糊。
- 交互按钮：可以使用 1–2px 的上边/左边高光和下边/右边阴影，表达“可按下”。
- 按下状态：阴影缩短，内容向右下移动 1px，确保状态在不依赖颜色时也能看懂。
- 输入框：深色内陷表面，焦点时使用 accent-bright 边框。
- 列表行：默认平面，选中行使用靛蓝侧边标记或反相，不为每一行添加独立卡片。
- 渐变只服务于硬件高光和按压层级，不用于装饰背景或制造发光。
- 所有系统组件保持直角；不使用药丸、胶囊、大圆角或漂浮圆形按钮。

### 4.3 字体与像素感

- 系统文字使用 ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, monospace。
- 作品标题和少数内容标题可以使用现有 serif 角色，形成系统文本与内容文本的分工。
- 不全站使用像素字体；像素感来自背景素材、点阵、有限色阶和组件细节。
- 系统标签短、具体、可扫描，例如 SYSTEM / WORKSPACE、OPEN、BUILD: 882.A。
- CJK 文字保持可读字号和正常字距，不为了模拟终端而强制压缩。

## 5. OS 信息架构

### 5.1 四层模型

~~~text
背景素材层
  └─ 图片 / GIF / 像素空间 / 时间氛围

系统壳层
  ├─ macOS skin
  └─ Windows skin

工作站与应用层
  ├─ 桌面状态面板
  ├─ 桌面入口
  ├─ 窗口
  └─ 应用内部组件

前景彩蛋层
  └─ Pen Pen / 低频故障和拖动反馈
~~~

每个新对象必须先归入其中一层。背景不能承载系统状态；应用不能直接修改系统壳层；Pen Pen 不能被烘焙进背景。

### 5.2 Workstation Desktop 布局

桌面不是空白画布，也不是信息仪表盘。默认布局包含：

- 顶部系统栏：时间、系统状态、当前空间和高频入口。
- 工作区：背景、桌面图标、状态面板和窗口层。
- 工作站信息面板：只展示与系统或作品集有关的少量实时信息，不堆叠独立卡片。
- Dock / 任务栏：展示已打开应用、常用入口和当前活动状态。
- Pen Pen：独立于系统壳层的前景对象，默认靠近右下区域。

信息密度规则：

- 桌面常驻面板应有明确的系统用途，不能只是装饰性数据。
- 同时出现的主要信息区域控制在 2–3 个；更多内容通过应用窗口打开。
- 工作站感来自稳定的区域、状态和窗口关系，不来自把所有内容同时铺满。
- 窗口打开后，应用内部可以比桌面更密，但仍沿用相同的间距、边框和状态语言。

## 6. 平台壳层策略

### 6.1 共享部分

macOS 与 Windows 两套 skin 必须共享：

- 颜色令牌；
- 字体角色；
- 间距和尺寸；
- 窗口生命周期；
- 按钮、输入、列表、菜单和对话框状态；
- active / inactive / minimized / restored / closed 语义；
- 键盘导航、focus ring 和多语言策略；
- 动效时间、按压反馈和 reduced-motion 行为。

### 6.2 macOS skin

macOS 是第一验收基准：

- 保留顶部菜单栏和底部 Dock 的空间关系；
- 可以保留交通灯作为窗口控制的熟悉识别，但不让其扩展为应用品牌色；
- 使用较轻的窗口层叠和 Dock 活动反馈；
- 窗口拖动、聚焦、最小化和恢复行为优先按 macOS 视图调校。

### 6.3 Windows skin

Windows 不复制真实 Windows 主题，而是提供同一 OS 的另一套平台 chrome：

- 使用任务栏、系统菜单和右侧窗口控制的空间关系；
- 复用同一套窗口内容和组件状态；
- 可以使用更明显的标题栏和按压反馈，但不能单独引入米色、绿色或新的品牌色；
- Windows skin 的差异只存在于系统入口、窗口控制、任务栏和少数布局适配。

## 7. 组件套件范围

### 7.1 系统级组件

- 系统栏 / 菜单栏；
- Dock / 任务栏；
- 桌面图标；
- 工作站状态面板；
- 应用启动器；
- 活动应用状态；
- Pen Pen 前景对象。

### 7.2 窗口级组件

- 普通窗口；
- 活动 / 非活动窗口；
- 标题栏；
- 平台窗口控制；
- 最小化、恢复、关闭；
- 拖动区域；
- 窗口堆叠和焦点管理；
- 窄屏全屏窗口。

### 7.3 基础控件

- 主按钮、次按钮、按下按钮、禁用按钮；
- 输入框、搜索框；
- Checkbox、Radio、Toggle；
- Tabs；
- List / List row；
- Menu / Context menu；
- Dialog；
- Toast / Notification；
- Progress / Loading；
- Icon button；
- Focus ring 和键盘选中状态。

### 7.4 内容组件

内容组件不应重新发明视觉语言，只在系统组件上定义布局：

- About 信息块；
- Writing 文章列表和阅读窗口；
- Contact 信息面板；
- 项目截图、照片、视频和代码内容；
- 文章中的标题、正文、元数据和引用。

## 8. 状态契约

每个可交互组件至少要定义以下状态：

| 状态 | 视觉反馈 | 行为反馈 |
| --- | --- | --- |
| default | 普通表面和边框 | 可操作 |
| hover | 高光或短距离抬升 | 暗示可操作，不改变布局 |
| focus | 清晰的 accent-bright focus ring | 键盘可继续操作 |
| pressed | 阴影缩短，内容轻微下压 | 立即确认按下 |
| selected | 靛蓝反相或侧边标记 | 表达当前项 |
| disabled | 降低对比度，不依赖透明度 | 不响应输入 |
| inactive | 窗口或应用层级降低 | 可以恢复焦点 |
| error / warning | 使用系统允许的高对比状态表达 | 必须有文字或语义补充 |

视觉状态不能成为唯一信息来源。图标、文字、 aria-pressed、aria-live 或等价语义必须同步表达关键状态。

## 9. 动效和交互

### 9.1 动效原则

- 普通 hover、focus、选择和窗口显隐：120–200ms。
- 按压反馈：优先改变阴影和位移，再改变颜色。
- 系统过程：使用 steps() 或离散帧，保持像素显示设备的感觉。
- 背景默认不做运行时持续运动；GIF 的运动来自素材本身。
- 动效不能让工作站信息面板或窗口内容持续漂移。

### 9.2 Pen Pen

- 默认使用白色单色形象，保留 PEN² 识别细节。
- hover 可以出现短暂的故障切片、几何碎片或轻微偏移，但不能持续闪烁。
- 长按拖动时进入行走或移动状态；释放后保留当前会话位置。
- 刷新或重新打开页面时回到默认右下位置。
- 拖动反馈必须可中断，并在 prefers-reduced-motion 下冻结为清晰状态。
- Pen Pen 的交互不能阻塞窗口、菜单、Dock 和键盘操作。

## 10. 迁移与实施顺序

### 子任务 1：建立新令牌和样式边界

交付：

- B 色彩令牌；
- Retro Hardware 表面令牌；
- 统一间距、边框、阴影、字体和状态令牌；
- 标记并隔离 blueprint 遗留变量。

验收：

- 新组件不再直接依赖旧的 --blue / --white 语义；
- 旧令牌仍可在兼容层暂时工作，但不能继续扩散。

### 子任务 2：重构基础控件

交付：

- Button、Input、List、Menu、Dialog、Toast、Tabs、Progress、Icon button；
- 完整状态矩阵；
- keyboard focus 和 reduced-motion 规则。

验收：

- 同一组件在 macOS 与 Windows skin 下只替换 chrome，不复制组件实现；
- 所有状态可通过键盘和语义属性验证。

### 子任务 3：重构窗口管理

交付：

- 统一窗口模型；
- macOS / Windows 标题栏和窗口控制 skin；
- active、inactive、minimized、restored、closed 状态；
- 桌面拖动、焦点、重复启动和窄屏行为。

验收：

- 同一应用不会重复创建无意义的窗口副本；
- 窗口焦点关系和系统栏活动状态一致。

### 子任务 4：重构 Workstation Desktop

交付：

- 顶部系统栏；
- 桌面状态区域；
- 桌面图标；
- Dock / 任务栏；
- 工作站信息面板；
- 统一桌面间距和遮挡规则。

验收：

- 桌面有工作站感，但不成为卡片墙；
- 背景、系统对象、窗口和 Pen Pen 的层级明确；
- macOS 视图先达到完整可用，再补 Windows skin。

### 子任务 5：迁移应用页面

迁移顺序：

1. About；
2. Writing；
3. Contact；
4. 其他内容和实验性应用。

交付：

- 应用只声明内容布局，不再独立维护窗口、按钮、系统栏视觉；
- 应用内部状态接入统一组件；
- 中英文日文的长文本在新组件中可用。

验收：

- 每个应用在打开、聚焦、关闭和窄屏状态下保持一致；
- 旧 blueprint 层级和应用特有色彩不再影响系统壳层。

### 子任务 6：背景、Pen Pen 和动效迁移

交付：

- 背景素材注册和切换契约；
- Pen Pen 新层级、单色处理和交互状态；
- 窗口和控件动效；
- reduced-motion 降级。

验收：

- 背景可以独立更换，不需要修改窗口和应用代码；
- Pen Pen 不会被背景、Dock 或窗口吞没；
- 没有运行时 ASCII、鼠标水波或全局漂浮效果。

### 子任务 7：清理和验收

交付：

- 更新 design.md，使其与本规格和最终实现一致；
- 删除或迁移 blueprint 遗留 CSS；
- 更新相关单元测试和 E2E 测试；
- 生成 macOS / Windows / 窄屏视觉验收截图。

验收：

- npm test 通过；
- 页面生成和静态资源检查通过；
- 远端构建使用包含本次 UI Kit 迁移的提交；
- 不存在只在本地工作但没有进入构建产物的样式或资源。

## 11. 代码边界与迁移原则

预期会涉及以下现有区域，但实施时必须按行为依赖链分批提交：

- 令牌与全局样式：styles/tokens.css、styles/shell.css；
- 窗口与系统壳层：styles/windows.css、styles/macos-mode.css、styles/windows-mode.css；
- 图标与桌面环境：styles/icons.css、styles/environment.css；
- 桌面和窗口行为：scripts/desktop.js、scripts/window-manager.js；
- 应用内容：styles/apps.css、styles/content-page.css、modules/；
- 设计文档：design.md；
- 单元和 E2E：tests/unit/、tests/e2e/。

迁移要求：

- 每个子任务只提交自己负责的行为链；
- 保留当前工作区中与本次 UI Kit 无关的未提交改动；
- 先建立共享令牌和基础组件，再迁移应用页面；
- 不允许为了快速换色而把新颜色硬编码到各应用样式中；
- 不允许在旧 blueprint 规则上继续叠加覆盖层；确认新组件可用后删除旧规则。

## 12. 风险与控制

### 风险：Retro Hardware 变成过度拟物

控制方式：渐变、内外阴影只允许出现在可操作控件和必要的窗口层级；普通内容区域保持平面和清晰。

### 风险：Density 2 变成信息拥堵

控制方式：限制桌面常驻信息区域数量，要求每个面板具备明确的系统用途；复杂信息进入应用窗口。

### 风险：Two Platform Skins 再次产生两套系统

控制方式：先实现共享组件和状态矩阵，再实现 skin；平台差异只允许存在于 system chrome 和入口布局。

### 风险：背景素材重新夺走系统层级

控制方式：背景素材预处理时保留安静区域，并通过系统对象的实体边框保证识别；不在运行时引入复杂遮罩和扰动。

### 风险：历史旧样式难以一次清理

控制方式：先建立新的令牌和组件边界，逐页迁移，并在最后以搜索、截图和测试共同确认 blueprint 规则已退出主路径。

## 13. 设计验收标准

本规格只有在以下问题都能得到肯定回答时，才算完成：

- 访客能在首屏感知这是一个完整的个人 OS，而不是普通网页套了桌面背景吗？
- B 色彩、Retro Hardware 表面和像素背景是否形成统一的夜间工作站气质？
- macOS 与 Windows 是否看起来属于同一个系统，而不是两个项目？
- 桌面信息是否足够表达 Workstation Desktop，但没有变成卡片堆叠？
- 窗口、按钮、输入、列表、菜单、对话框和通知是否共享同一套状态语言？
- active、hover、pressed、focus、selected、disabled 和 inactive 是否都清晰可辨？
- Pen Pen 是否是独立且可识别的彩蛋，而不是背景中的装饰？
- 在窄屏、200% 缩放、中文、英文、日文和 reduced-motion 下，系统是否仍然可操作？
- 旧 blueprint、ASCII 背景和运行时鼠标扰动是否已经退出默认路径？
