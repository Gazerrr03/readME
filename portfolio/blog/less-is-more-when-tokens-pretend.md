# 前言

我读《人月神话》的时候，总觉得哪里眼熟。不是眼熟书里的道理——「加人更慢」这句话我听过太多次，耳朵都起茧了——是眼熟我自己干过的蠢事。1975 年，Brooks 在书里写，任务是任意不可切的，「人月」是个神话：往一个已经延误的项目里加人，只会让它更延误。分配九个女人，也生不出一个孩子。

五十年后，我们发明了另一个单位，叫 token。Tibo 出圈之后，「烧 token」成了努力程度的度量衡。社区发明了「重置前冲刺」，有人晒出一天烧掉的百万 token；省着用，反而像一种亏。

两个时代隔了半个世纪，错在同一个地方。人类在 AI 面前，用两种方式假装努力：**把消耗当成产出，把愿望当成工作。**我们不是没读过这本书——我们是把它换了一身衣服，又犯了一遍。

# 把窗口开满，等于没开

我最近就干过这么一件事。一个很小的项目，为了快速拼功能，我一次性开了六个并行的 Agent 窗口。

六，是一个看起来很努力的数字。当时我觉得自己在并行——像把六个线程塞进六个核。但人不是机器，人的 review 只有一个线程。

会开六个，有一个更现实的原因：那阵子有个朋友说，他有一个 Kimi 的 API 可以给大家用。免费的额度，不用白不用。我把「不用白不用」直接翻译成了「六窗齐开」。结果 token 烧得特别快——快到我一度以为是出了故障——而我想搭的内容，远远没有搭完。

六份输出堆在桌面上，我一份一份看。看得越慢，堆得越高；堆得越高，我越心虚；越心虚，越不敢用；越不敢用，就越只能自己重写。最后那六个窗口的产出，是零。不是六个一，是零。

我原本以为并行是省时间。但省时间的幻觉，来自没算上 review 的成本。窗口可以开六个，review 的人还是只有我一个——它是常数，不随窗口数量线性上涨。Brooks 说加人更慢，因为沟通成本按 n(n-1)/2 涨；在 Agent 这儿，沟通成本换成了 review 成本。而 review，是那个不动的常数。

# 它还是一台许愿机

但六窗齐开，不只是「没时间 review」。它侧面说出了很多人对 AI 的默认认识：AI 还是一台许愿机。更有甚者，是一台你睡觉时也能自动实现愿望的许愿机——你站在它面前，许一个愿，愿望就实现了。好像它站在那里，剩下的都是它的事。

这当然不完全是错觉。模型能力在增强，AI 确实越来越像一台许愿机；很多所谓的黑客松优秀作品，也不乏是 AI 力大砖飞的结果。可「越来越像」和「真的是」之间，隔着一个东西：责任。

许愿不需要负责，review 需要。当你只是许愿，窗口开几个都无所谓；当你要为一个复杂系统负责，负责的人就只剩下你一个——这才是并行救不了你的地方。

所以《人月神话》在这一课里的作用，不是「少开几个窗口」这样的操作建议。它真正在说的是：当我们想在一个复杂系统里承担更多责任时，AI 并没有成为解决传统软件工程问题的银弹——它只是把复杂度换了种更便宜的形式，再原封不动地还给你，还到 review 里。银弹之所以是银弹，是因为它能一击消灭复杂度；而 AI 改变的只是复杂度的形态，没有改变它的重量。

后来我发现，这一课真正要讲的，不是「别开六个窗口」。真正要把人拖进焦油坑的，从来不是多开的那些窗口，而是你把 AI 当成许愿机的那份信任——对「更多」这件事本身的信任。

# 把「好」拆成两半：质量，和易于审核

那什么才算 token 花得值？我给自己定了一把尺子：**在尽量少的 token、尽量少的时间里，交付一个既好、又容易审核的结果。**

这里「好」我特意拆成两半：质量高，**以及**易于审核。

很多人只数前半段。但我想说的是，一个「质量高但难审核」的结果，其实是低效的——它把最贵的资源，人的注意力，花在了二次理解上。生成的代价是便宜的，理解的代价是贵的；产出是便宜的，验收是贵的。

所以「易于审核」不是锦上添花，它就是效能本身。顺着这把尺子推下去，方法论自己就长出来了：守住一两个窗口，把 AI 生成的内容严格 review 好。窗口少，token 少，review 清——这才叫真正把控这个项目，效率也才起得来。

# 为烧而烧：被制造出来的努力

如果只是我个人的一次翻车，不值得写。真正让我警惕的是，这种翻车正在变成一种文化。

为烧而烧，我猜背后至少有三层结构。

第一层，是表演性。token 数变成了努力程度的可见刻度。有的模型一个指令下去自动跑十几轮，两分钟烧光五小时额度——烧得多，看起来就投入。这是新的社交货币。当年老板吹「我团队两百人」，今天有人晒「我今天烧了五百万 token」。数字换了，虚荣没换。

第二层，是激励扭曲。「省着用反亏」——额度重置让省 token 变成纯粹的损失，烧光反而可能赶上又一次重置。所以对个人来说，烧光是一个理性策略。不是人蠢，是激励机制在奖励浪费。当理性本身被扭曲，浪费就成了理性。

第三层，是一个不那么善意的猜测：平台也许乐见其成。Tibo 的「赛博义父」人设，每一次重置都是一场新闻事件、一个社区话题、一波流量高峰——把「额度」变成产品的记忆点，把「烧 token」变成使用习惯。这一层我写的是猜测，不是结论。但猜测也是一种观察：一家商业公司无偿地做慈善，总该有个理由。

这三层不是并列，是互相喂养的：平台用 reset 制造激励，激励养出「烧等于努力」的文化，文化反过来给平台的增长提供燃料。所以为烧而烧，不是个体道德问题，是被结构制造出来的。在一个被结构制造出来的问题面前，指责个体，是廉价的。

# 当 token 变成按人头发的额度

为什么我那天会开六个窗口？——因为那一刻 token 是免费的，是朋友给的 API。免费的资源，人不会珍惜。这句话老掉牙，但在 AI 时代它有了新的重量：因为 token 不会一直免费下去。

我猜，很快会有企业按人头给每个员工发 token 额度。额度有限，用完即止。到那时候，问题就变了：不可能有一个人把 token 烧完了、却什么都没做出来，然后回头去找企业申请扩充额度。不是说不能申请——而是前提变了：**申请扩充额度之前，你得先交付足够支撑起这么多额度的信任的价值。**

额度不是预算，额度是信任的抵押品。你能拿到多少，取决于你上一次交付了多少价值；而你上一次交付的价值，就是你下一次申请额度的信用。1975 年，管理者按人头记账；2026 年，企业按 token 记账——但账本上写的，还是信任。

# 第一版靠无知克制，第二版靠懂了放纵

烧 token 是资源侧。另一侧是机制侧——Skill 越堆越多。

Brooks 在《人月神话》里有一章叫「画蛇添足」：设计师的第二个系统最危险。第一版克制，是因为你还不懂；第二版憋了一肚子想加的功能，终于有机会全塞进去，于是过度设计。Skill 堆到一定规模，就成了焦油坑——你已经投入了那么多，出不来了。

AI 工作流完全一样。我收藏过很多做 PPT 的 Skill——「懂」了这个机制之后，觉得这个可能有用、那个可能有用，于是全都收进来。可如今回看，真正高频用到的，或许只有一两个，而且恰恰还是「不懂」的时候、因为真需要才收的那一两个；后面那批「懂了」之后收的，绝大多数我根本用不上。

用不上的 Skill，代价不只是「躺在那儿」。它们每次对话都还是会被加载进上下文——收藏的那一下是免费的，但从此每一次会话，它们都占着宝贵的上下文空间。这让我想起那篇《沉积与种子》：记忆的价值不在于记得多，而在于能否改变未来的决策。一个不被使用的 Skill 就是这样一种记忆——它记得，但它从不改变任何决策，只是白白占着位置。

这里的悖论是：第一版不是靠自律克制的，是靠无知克制的。你因为不知道还能加什么，所以只加了必须的东西。等你懂了，懂本身就变成了负担——你知道了太多「可能的方向」，于是每一个方向都显得不够好。

从那以后我给自己立了一条规矩：每加一样东西，先问一句——它是承重，还是装饰？装饰的，不留。

# less is more 不是少，是让结构站出来

所有这些，到最后其实是一句话：少即是多。

密斯·凡·德·罗说 less is more，被误读了很久。大家以为说的是「少放点东西」，像把一个房间清空。但密斯讲的从来不是删减，是让结构自己站出来。范斯沃斯住宅 almost nothing——玻璃盒子几乎空无一物，可钢柱、玻璃、比例精确到骨头里。「上帝在细节里」和「less is more」是同一个人说的。他的少，是剥掉一切不承重的装饰，让承重的东西精确地立在那里。少不是空，少是精确。

《人月神话》里的概念完整性，是同一句话的另一个版本：系统应该呈现一个思想，而不是一堆东西的堆积。Brooks 说这是系统设计里最重要的一条，要靠架构出自一个头脑来保证。

还有「没有银弹」：软件的复杂度分本质和偶然，工具只能打掉偶然的那部分，打不掉本质。我上一篇博客里写过，「Skill 降低的是执行成本，不是判断成本」——判断成本就是本质复杂度。它删不掉，加再多的 Skill 也删不掉。

所以 less is more 不是审美，是工程纪律。每多一个不承重的组件，都在稀释那个唯一的思想。

# 巴别塔教我们要沟通，兰斯教我们忍得住

《人月神话》用巴比伦塔讲沟通：语言一乱，塔就建不成。但我想讲另一座建筑。

兰斯大教堂，法国历代国王加冕的地方，建了近一个世纪，一代代匿名的石匠接着干。没有人画过今天意义上的总图，没有人和所有人说明白过每一块石头——可它偏偏是哥特建筑里整体性最好的作品之一。秘密不在沟通，在克制：每个石匠守着自己的贡献域，用同一套结构语法，忍住自己多余的发明。

巴别塔和兰斯大教堂，教的是相反的两课。巴别塔说：不沟通会失败。兰斯说：信任和分工足够清晰时，不沟通反而是美德。在这个什么都急着对齐的时代，「收起一些自己的点子」听起来像消极；但在一个能彼此交付信任、贡献域清晰的团队里，它恰恰是积极的——它把空间，让给了真正属于你的那块。

第二系统效应讲的是设计师憋不住自己的点子；兰斯的石匠证明，憋得住，才建得出。

这也让我重新想概念完整性。Brooks 说要靠一个头脑，兰斯说：没有那一个头脑，也可以靠一套共享语法。两句话不矛盾——当每个人都内化了同一套语法、守住了自己的域，其实每个人都成了那同一个头脑。概念完整性未必需要一个英雄建筑师，它可以是一个被所有人共享、又被所有人守护的结构。

# 正交：克制史的总账本

落到操作层面，我给自己定的停止条件是：当一个 Skill 或 Agent 的存在，开始需要我「解释它是干嘛的」、而不是「它自己在干活」的时候，就该删了。它不再产生输出，它产生的是记忆负担。

一个健康的 Skill 系统，我理解是：大部分的 Skill 都覆盖在我主要的工作域里，并且 Skill 与 Skill 之间的语义尽可能正交。

正交这个词听起来像技术洁癖，但我想说它不是。正交是所有人克制史的总账本——每个 Skill 的边界，都是一个「忍住没加的点子」留下的位置。两个 Skill 语义重叠，模型就得现场判断用哪个；这种「现场判断」，就是概念完整性被稀释的症状。

三个信号，任何一条出现就做减法：review 跟不上了，输出在堆积；开新窗口、加新 Skill 变成了习惯，而不是因为确实有个缺口；列表长到我自己都记不清每个是干嘛的。

一个覆盖 90% 工作域的正交小库，健康过一个覆盖 10% 工作域、却收罗了五十个旁门 Skill 的大库。前者是结构，后者是仓库。

# 把决定权拿回来：要不要加，加到哪

AI 越来越便宜，克制反而越来越贵。真正稀缺的从来不是算力，是判断和注意力——是人 review 的能力，是人决定「什么值得继续」的能力。

上一篇我说，要夺回决定信息如何进入自己的权力。这一篇我想补下半句：还要夺回决定「要不要加、加到哪」的权力。信息过载和机制过载，是同一场病的两个阶段——一个塞进来太多，一个加进去太多。

少即是多，说的从来不是「什么都不做」。它说的是：多，只有在没有顶到天花板的时候才是多。而我们的天花板，是人。

密斯的墙是可以拆的，但拆完你要能说出，剩下的每一根柱子为什么在这里。说不出理由的，就是该拆的墙。
